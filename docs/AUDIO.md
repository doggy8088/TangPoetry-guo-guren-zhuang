# Audio pipeline: 《過故人莊》

All narration is generated by Google Gemini TTS, checked by an automatic transcription QA loop, and cleaned up with ffmpeg. The background music is synthesized in Node with no samples. Everything is reproducible from `script/narration.json`.

## Outputs

| Path | What |
|---|---|
| `audio/cues/<cue-id>.wav` | One clip per cue: 24 kHz mono 16-bit, silence-trimmed, about -16 LUFS |
| `audio/cues/<cue-id>.json` | Sidecar: text, voice, exact prompt, measured duration, QA result and every attempt's transcript |
| `audio/vocab/NN.wav` (+ `.json`) | Vocabulary clips read by the 旁白 voice as `「詞」，意思。`. `NN` is the zero-padded index into `narration.json` `vocab` (`00` = 過 … `22` = 菊花); `timeline.json` `vocab_audio` maps word to path |
| `script/timeline.json` | `{ fps, total, scenes[], cues[], vocab_audio }`, built from measured clip durations |
| `audio/narration.m4a` | Whole narration track, each clip at its timeline start: AAC 128k, 48 kHz stereo, faststart |
| `audio/narration.mp3` | The same track as MP3 192k (fallback) |
| `audio/bgm.wav`, `audio/bgm.m4a` | 64 s seamless background loop, peak -20 dBFS |

## How to run

```bash
export GEMINI_API_KEY=...        # never committed, never printed
npm run tts                      # generate missing/changed clips, then rebuild timeline, merged track and the QA table below
npm run tts -- --force           # regenerate every clip
npm run tts -- --only s1-3,s2-1  # regenerate just these clips (cue ids, vNN, or a vocab word such as 雞黍)
npm run tts -- --concurrency 2   # default is 4
npm run bgm                      # re-synthesize audio/bgm.wav + bgm.m4a (deterministic, no API)
```

Re-runs are incremental. A clip is reused when its `.wav` exists and its sidecar records the same text, voice and prompt with `qa.pass === true`. Clips that ended as WARN are regenerated on every plain run. `--only` always regenerates the listed clips and reuses every other clip as it is. The timeline, the merged narration and the QA table are rebuilt on every run. That step makes no API calls and takes under a minute on an idle machine.

## How it works

### 1. Prompt (TTS model `gemini-3.8-flash-tts`)

The style direction is the English `speakers[speaker].direction` from `narration.json`. It has to be inside the prompt because `systemInstruction` returns 400. Prompt layout:

```
### DIRECTOR'S NOTES
<direction>

### TRANSCRIPT
<line>
```

**Why not the plain `<direction>\n\n<line>` layout:** in tests on 2026-10-05, the plain layout made the model read the English direction aloud before the line in **7 of 8** generations, which added 12 to 20 s of English. Other layouts: a `Transcript:` label leaked in 3 of 8, and a `Say the following line exactly:` suffix in at least 5 of 8. The DIRECTOR'S NOTES / TRANSCRIPT layout, taken from Google's TTS prompting guide, leaked in **1 of 26**. Leaks still happen occasionally, which is why the QA loop exists.

### 2. QA loop (up to 4 attempts per clip)

Each attempt is trimmed and loudness-normalized first, then checked. Transcription always runs on a **QA copy padded with 0.5 s of silence on both sides**; the delivered clip itself stays trimmed (see *Findings* below for why).

| Check | Rule |
|---|---|
| Similarity | Transcript from `gemini-2.5-flash` with `請逐字轉寫這段音檔的內容（繁體中文），只輸出轉寫文字。`. Both strings are normalized (punctuation, whitespace, 「」〈〉 and symbols removed, lower-cased, NFKC, CJK digits folded to 0-9), then scored with the Levenshtein ratio. Must be at least **0.85** for cues and **0.75** for vocab clips |
| Homophone fallback | If a character-level score misses, the reference and the transcripts are converted to toneless pinyin (one structured `gemini-2.5-flash` text call), and the syllable-level Levenshtein ratio is used when it is higher. Homophones such as 黍→薯, 庭→婷, 至→志 and 邀→妖 then count as matches. These scores are marked **(py)** in the tables. For **cues**, a pass that relies on pinyin does not end the loop: the loop keeps trying (up to 4 attempts) for a take that also passes at character level, then keeps the take with the best character-level score. Vocab clips accept pinyin passes |
| Length | Transcript length must be at most 1.25 × text length |
| Telltales | Neither transcript may contain instruction words (narrator, voicing, Mandarin, verbatim, director, transcript, 導演, 指示, 語氣, 旁白：, 台灣, 國語, …) or English words typical of the directions (the, are, of, read, only, voice, story, girl, boy, …). Pinyin output such as "pa" for 把 is not counted as a leak |
| Head check | The first 6 s are transcribed again, in the original language (English stays English). The result must have no telltales and must match the start of the text (prefix similarity of at least 0.4, by characters or by pinyin) |
| Speech rate | Trimmed duration must be at most 2.5 s + chars / 2.0 s |

The first attempt that passes is kept. If none passes, the best-scoring attempt is kept (structural failures are heavily penalized) and the clip is listed as **WARN** below with every transcript, so that a person can decide. API calls retry on network errors, HTTP 429 and 5xx with backoff of 1, 2, 4 and 8 s (a longer server `retryDelay` wins). Clips run 4 at a time.

### Findings that shaped the QA (2026-10-05)

1. **Instruction read aloud, hidden from the transcript.** When the TTS model reads the English direction aloud, transcribing the *whole* clip usually returns just the Chinese line, with similarity 1.00. The transcriber obeys the spoken "Read ONLY the text below" and leaves out the English. Six of twelve known-bad test clips scored 0.75 to 1.00 on the full transcript, five of them a perfect 1.00. The head check and the speech-rate check rejected **all 12**, and all 6 known-good clips passed.
2. **Tightly trimmed clips lose their edge syllables in ASR.** 我們下次見 was transcribed as 我們見 or 我們下個, and 「至」，到 as 至. The same clips padded with 0.5 s of silence were transcribed correctly 3 of 3 times, so the audio is intact. Before this fix, the first full run ended with 9 false WARNs. Since then, QA transcribes padded copies.
3. **Pinyin can hide a real mispronunciation.** In the first complete run, s7-7 開軒面什麼 was heard as *tái xuān* in 3 of 3 transcriptions plus a pinyin transcription, and s7-3 故人具 as *qù*. Both passed on pinyin similarity (0.9), because one wrong syllable in ten still scores 0.9. These are poem words in the recitation challenge, so cues now keep trying for a character-level pass (see the rule above). The regenerated s7-3 and s7-7 transcribe exactly (1.000). s7-8 stayed at character level 0.8 in all 4 takes, but only because of a true homophone (場→長) and correct tone sandhi (把酒 *bǎ jiǔ* → *bá jiǔ*, written 拔). That audio is right.
4. **Single-character vocabulary is ambiguous to ASR.** 「邀」，邀請 was transcribed as 妖妖請, and 「合」 as 河. Two to five normalized characters leave no room for one homophone, which is why the pinyin fallback exists.
5. **What the final run caught.** The final forced run plus the s7-3/s7-7/s7-8 regeneration made 86 generations. They included 2 direction leaks (v21 attempt 1, in English, with full-transcript similarity 1.000; v01 attempt 3, a Chinese rendering of the direction) and 3 invented story intros such as 大家好，我是熊寶寶故事的主持人 (v01 attempts 1 and 2, v04 attempt 1). All were rejected automatically, and the details are in the table below.

### 3. Post-processing (ffmpeg, `scripts/lib/audio.mjs`)

- Trim silence: `silenceremove` at the start, `areverse`, `silenceremove` again, `areverse` (-45 dB threshold, 80 ms of silence kept at each end).
- Two-pass `loudnorm` (I = -16 LUFS, TP = -1.5 dBTP, LRA = 11): the first pass measures and the second applies a linear gain, so speech dynamics are not pumped.
- Output: 24 kHz mono s16le WAV. Durations are measured with ffprobe.

### 4. Timeline rules (`script/timeline.json`)

- `t = lead_in`. Each cue gets `start = t` and `end = start + duration`. The next cue starts at `end + gap + pause_after`, where `gap` is `gap_scene` when the next cue is in a different scene and `gap_cue` otherwise.
- Scene `start` = first cue start - 0.6 s. The **first scene starts at 0**, so that scenes cover `[0, total]` with no gaps. Scene `end` = next scene's start; the last scene ends at `total`.
- `total` = last cue end + `tail`. All times are rounded to 3 decimals.

### 5. Merged narration

ffmpeg `adelay` (in samples, `NNNNS`) places every clip on an `anullsrc` bed exactly `total` seconds long, and `amix` (`normalize=0`) mixes them. The 24 kHz master is then **verified in Node**: it must contain exactly `round(total × 24000)` samples, and every clip must appear bit-exact at `round(start × 24000)`. Placement is therefore exact to within one sample (0.04 ms). The master is encoded to `narration.m4a` and `narration.mp3`, and both durations are checked with ffprobe against `total` (±0.05 s).

## Background music (`scripts/bgm.mjs`)

<!-- BGM:BEGIN -->
- C major pentatonic (C D E G A, C4 to A5), **75 BPM**, 4/4, 20 bars = **64.000 s** exactly. The tempo was nudged from about 72 to 75 BPM so that the loop is bar-aligned. Seeded PRNG (mulberry32, seed `0x9e0b2026`), so every run gives the same file.
- Pluck timbre: sine partials 1× + 2× (-12 dB) + 3× (-20 dB), 4 ms attack, exponential decay (fundamental τ = 0.45 s; upper partials decay faster), plus a 0.3 % onset pitch settle for a guzheng feel. Brighter notes are played a little softer. The highest partial is about 2.6 kHz, so nothing is harsh.
- Melody: four seeded 2-bar phrases (random walk over the scale, rests included) arranged A B A′ C | B D A″ C | B′ cadence. Each phrase ends on a chord tone; some long notes get a soft lower harmony; some phrases start with a guzheng-style 3-note grace sweep.
- Drone pad: root + fifth (C, Am, Dm, G), slightly detuned sine pairs, 1.6 s swell and 2 s release, one pad per 2 bars.
- Reverb: Freeverb-style feedback-delay network (4 damped combs, feedback 0.8, plus 2 all-passes per channel, offset for stereo), wet 0.32.
- Loop: the last 2 bars are a cadence followed by rest, the final 1 s fades to silence (raised cosine) and the track starts from silence. The largest sample in the first and last 10 ms is -90.3 dBFS, so the loop does not click.
- Level: peak **-20.0 dBFS**, RMS -36.4 dBFS. It is meant to sit under the narration at about 0.25 volume.
- Files: `audio/bgm.wav` (48 kHz stereo s16, 64.000 s) and `audio/bgm.m4a` (AAC 128k, 64.000 s; AAC adds encoder padding, so use the WAV or WebAudio when a sample-exact loop matters).
